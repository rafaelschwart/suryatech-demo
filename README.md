# SuryaTech Response Desk

Operating dashboard for Suryatech EV Power LLC as a vendor on the Massachusetts VEH122 statewide contract. Built by Arqentia on the Studio Admin template (Next.js 16, Tailwind CSS v4, shadcn/ui), with a SuryaTech theme preset.

## What it does

The dashboard has two halves, and the overview shows both.

**Overview** (`/dashboard/overview`): fleet numbers, the map, one line per station, then the next filings, the requests worth a response and the state of the response pipeline. Every block links to the section that owns it.

**Project operations** (Phase 2, simulated)

| Screen | Route | What it achieves |
|---|---|---|
| Locations map | `/dashboard/operations` | Seven stations across greater Boston on a Leaflet map; click a marker or a row for status, live readings, today and 30-day sessions, revenue, connectors, faults, the 90-minute curve and a power check |
| Power and performance | `/dashboard/stations` | The station console: telemetry, energy flow, the 3D unit, remote commands over the OCPP-style API, every call shown. `?station=ID` preselects |
| Sessions and revenue | `/dashboard/revenue` | Cars charged, energy delivered and revenue, today and over 30 days, per station and per day, with uptime |

**Package preparation**

| Screen | Route | What it achieves |
|---|---|---|
| Deadline board | `/dashboard/deadlines` | Every date Suryatech owes, on one board: request closings, SDP report, MBE renewal, MassCEC milestones |
| Opportunities | `/dashboard/opportunities` | Watches the COMMBUYS public bid search, records every VEH122 request, and gives each a Chase / Consider / Pass verdict with reasons |
| Response assembler | `/dashboard/assembler` | The buyer's required format (MAPC, seven tabs) filled from the company record and the library, with what is missing counted per tab |
| Answer library | `/dashboard/library` | Company constants, scope blocks, rate card, references, form templates, written once |
| Evidence register | `/dashboard/evidence` | Recurring compliance obligations with cadence, next date and the document that proves them |
| Export pack | `/dashboard/export` | The response folder named the way the RFP names it. Builds locally; never uploads |
| Documents | `/dashboard/documents` | Nine sample PDFs, one or more per stage |

Only the Lowell station comes from the public record; the other six are illustrative placements on real public lots (Newton, Milton, Cambridge, Braintree, Somerville, Lynn). Map tiles are Esri's light-gray canvas, no key required.

## Data honesty

Every screen opens with a provenance line. Three labels are used consistently:

- **Public record**: read from COMMBUYS, mass.gov, the Lowell filing or LinkedIn. No account was used.
- **Sample**: stands in for Suryatech material that has not been seen (rates, references, certification dates).
- **Simulated**: generated by the station simulator in `src/server/stations/simulator.ts`. Nothing is connected to a live charger.

Nothing in the app writes to COMMBUYS or any Commonwealth system.

## API routes

| Method | Route | Purpose |
|---|---|---|
| `POST` | `/api/watcher/run` | Replays the last verified COMMBUYS search result. `{ "simulateNew": true }` adds one invented posting to show the alert flow |
| `GET` | `/api/stations` | Live snapshot of every station |
| `GET` | `/api/fleet/summary` | Fleet totals: online, charging, output, sessions and revenue today and over 30 days, per station |
| `GET` | `/api/fleet/history?days=30` | Daily sessions, energy and revenue across the fleet |
| `GET` | `/api/stations/:id` | One station |
| `GET` | `/api/stations/:id/telemetry?minutes=90` | MeterValues history, one point per minute |
| `POST` | `/api/stations/:id/commands` | `PowerCheck`, `RemoteStartTransaction`, `RemoteStopTransaction`, `ChangeAvailability`, `Reset`, `GetDiagnostics`, `TriggerMessage` |

The command shapes mirror OCPP, the charge-point protocol a real management system would speak.

## Hosting

Live demo: **https://suryatech.demo.arqentia.com** (GitHub Pages, repo `rafaelschwart/suryatech-demo`). Every push to `main` rebuilds and redeploys through `.github/workflows/pages.yml`; DNS is the existing wildcard `*.demo.arqentia.com` → `rafaelschwart.github.io`, with `public/CNAME` naming the host.

GitHub Pages is static, so the hosted build has no server. `npm run build:static` (`scripts/export-static.mjs`) parks `src/app/api` for the duration of the build, exports the site to `out/`, and sets `NEXT_PUBLIC_API_IN_BROWSER=1`, which makes `deskFetch` (`src/lib/desk-api/client.ts`) answer `/api/*` from the simulator in the browser tab. The route handlers and the in-browser adapter call the same functions in `src/lib/desk-api/handlers.ts`, so paths, methods, status codes and payloads are identical. The Stations and Opportunities screens say so in their provenance lines when the flag is on. `npm run dev` and `npm run build` keep the real route handlers.

## Run

```bash
npm install
npm run dev        # http://localhost:3000
npm run build          # server build, with /api route handlers
npm run build:static   # static export for GitHub Pages → ./out
npm run check      # Biome lint and format
```

## Media

`public/media/` holds the Higgsfield renders used in the interface: the transparent charger cutout, the energy-flow diagram and three site renders. All are labeled Illustration on screen. Drop a `charger.glb` (image-to-3D of the cutout) into the same folder and the station stage switches from the tilt render to an interactive 3D model automatically.

### Finishing the 3D model when the Higgsfield daily limit resets

The charger cutout was generated as Higgsfield job `75146596-632a-4bab-bc18-d574ba81ce2d` (gpt_image_2_5, transparent 2k). The image-to-3D step was refused by the account's daily generation limit. To finish it:

1. `generate_3d` with model `tripo_h3_1_image_to_3d`, `medias: [{ role: "image_references", value: "75146596-632a-4bab-bc18-d574ba81ce2d" }]`, `texture: true`, `pbr: true`, `texture_quality: "detailed"`, `orientation: "align_image"`.
2. Download the resulting GLB to `public/media/charger.glb`.
3. Reload `/dashboard/stations`. The stage detects the file and switches to the interactive `model-viewer` renderer.

The sixth diagram (the five-step response process, isometric, 21:9) was refused by the same limit; the board draws that strip in code instead, so it is optional.

## Sample documents

`/dashboard/documents` lists nine sample PDFs, one or more per stage, on SuryaTech letterhead: opportunity intake sheet, morning watch digest, Tab 1 cover letter, Tab 3 experience, Tab 7 price proposal summary, submission pack manifest, submission record, SDP spending report, station power check report. They live in `public/documents/` with page-1 thumbnails in `public/documents/thumbs/`. Each carries a SAMPLE footer; company facts and the MAPC request are public record, everything Suryatech has not shared is a marked placeholder. The generator (HTML to PDF through headless Chrome, US Letter) is `scripts/gen_docs.py`; run it with Python 3.12 (PyMuPDF installed) after changing copy.

Full generation plan for the remaining visuals and animations: `docs/higgsfield-plan.md`.
